# CF Mail / CloudMail SLO v1

This document implements the first operational baseline from the industrial audit. It does not replace provider SLAs.

## Service objectives
- Worker API availability: >= 99.9% monthly for authenticated core API, excluding planned maintenance.
- Mail send accepted success: >= 99.5% excluding downstream provider rejection.
- Remote push handoff success: >= 99.5%; Push Gateway DLQ must be zero during steady state.
- D1 migration: 100% success before production deployment continues.
- iOS crash-free sessions: >= 99.8% for the current production build.

## Required alerts
1. Worker 5xx ratio > 1% for 5 minutes.
2. Mail send internal failure > 1% for 10 minutes.
3. Push Gateway DLQ depth > 0 for 5 minutes.
4. D1 migration/init workflow failure: immediate page/block deploy.
5. iOS crash-free sessions < 99.8% over 24 hours.

## Release gates
- `/api/health` must return HTTP 200 and `ready=true` after deployment.
- Cloud-Mail 3.0.0 compatibility tests must remain green for CF Mail iOS.
- No deployment proceeds after a migration, runtime-test, or release-archive gate failure.
